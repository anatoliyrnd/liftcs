 HANDOFF: Переход Lift-Calls на реальный Бэкенд (Мультитенантность)
Статус: Фронтенд полностью готов (API v4.0 интегрирован). Переходим к написанию реального бэкенда на PHP 8.3+ с использованием PDO.

🏗️ Утвержденная Архитектура (Multi-Tenant)
Master DB (Глобальная база):

Хранит адресное пространство: lift_city, lift_street, lift_home, lift_object (единые для всех).

Таблица lift_organizations: содержит org_key, название и реквизиты подключения (host, dbname, user, password) к базе конкретной организации.

Tenant DB (База организации):

Хранит пользователей (lift_users), заявки (lift_calls), историю и настройки.

Таблица lift_lkds_bindings: связка глобального object_id с локальным lkds_domain_id для интеграции со Spult.

Таблицы групп: lift_groups и lift_group_objects (связь с глобальными ID лифтов/домов/улиц).

Интеграция со Spult: Односторонняя. Spult присылает XML -> бэкенд парсит -> TicketService создает/объединяет заявку. Автосоздание адресов из XML запрещено (только логирование ошибок).

📝 ЧЕК-ЛИСТ БЭКЕНДА (Что нужно сделать)
Этап 1: Ядро и Подключения

□ Адаптировать PDODB.php под пул подключений (Master + Tenant).
□ Создать OrgManager.php (по org_key находит реквизиты в Master DB и инициализирует нужную Tenant DB).
□ Создать AuthService.php (генерация токенов, проверка паролей, refresh-куки).
Этап 2: Сервисы логики

□ Создать TicketService.php:
Логика createOrMerge (дедупликация по лифту+типу+отделу, запись дублей в call_details).

Поддержка offline_uuid для идемпотентности офлайн-пачек.

Транзакции для пачек.

□ Создать PermissionService.php (проверка прав на основе групп: какие лифты видит инженер).
□ Создать GroupService.php (логика наследования групп: улица -> дом -> лифт).
Этап 3: Эндпоинты (API)

□ Написать auth.php (login, refresh, logout, validate).
□ Написать api.php (замена test_calls.php): open, close, callnew, callNewOffline, calledit, callClose, callnote, get_user_settings, save_user_settings, check_org_key, get_org_users.
□ Переписать xml.php (Spult) с использованием TicketService.
Этап 4: Миграции БД

□ Написать SQL-миграции: offline_uuid в lift_calls, поля профиля и user_role в lift_users, таблицы lift_refresh_tokens, lift_organizations, lift_lkds_bindings, lift_groups.
