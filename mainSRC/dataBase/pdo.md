📚 Инструкция по работе с классом PDODB
Класс PDODB — это Singleton-обертка над PDO. Он использует подготовленные выражения (защита от SQL-инъекций), автоматически логирует ошибки в файл и умеет переподключаться к базе при потере соединения (например, при таймауте MySQL).

Требования: PHP 8.3+, MySQL 5.7+ / MariaDB 10.3+.

1. Инициализация
   Благодаря паттерну Singleton (Одиночка), соединение с базой создается один раз за время работы скрипта. Просто вызывай getInstance().

php
use mainSRC\dataBase\PDODB;

// Получаем экземпляр класса
$db = PDODB::getInstance(); 2. Базовые запросы
SELECT (Получение данных)
Для получения одной строки используйте row(). Возвращает ассоциативный массив или false.

php
$user = $db->row("SELECT \* FROM lift_users WHERE id = :id", ['id' => 1]);
// Результат: ['id' => 1, 'name' => 'Иван', ...] или false
Для получения нескольких строк используйте query(). Возвращает массив массивов.

php
$users = $db->query("SELECT \* FROM lift_users WHERE role = :role", ['role' => 'dispatcher']);
// Результат: [ ['id' => 2, 'name' => 'Петрова'], ['id' => 4, ...] ]
Если нужно получить одно конкретное значение (например, COUNT, MAX, SUM или просто одно поле):

php
$count = $db->single("SELECT COUNT(\*) FROM lift_calls WHERE status = 'open'");
// Результат: число (например, 42)
Если нужен массив значений одной колонки (например, только ID):

php
$ids = $db->column("SELECT id FROM lift_calls WHERE active = 1");
// Результат: [35732, 35733, 35734, ...]
INSERT (Вставка данных)
Класс сам соберет SQL-запрос по массиву. Метод insert() возвращает lastInsertId (ID новой записи) или false при ошибке.

php
$newUserId = $db->insert('lift_users', [
'name' => 'Новый Диспетчер',
'login' => 'disp2',
'role' => 'dispatcher'
]);
UPDATE (Обновление)
Передаем имя таблицы, массив изменений (SET) и массив условий (WHERE). Возвращает количество обновленных строк.

php
$affectedRows = $db->update('lift_users',
['name' => 'Новое Имя', 'role' => 'engineer'], // SET
['id' => 5] // WHERE id = 5
);
DELETE (Удаление)
Для удаления используйте метод query(). Возвращает количество удаленных строк.

php
$deleted = $db->query("DELETE FROM lift_refresh_tokens WHERE expires_at < NOW()"); 3. Продвинутые возможности (Специально для Lift-Calls)
🔥 Работа с массивами в IN (...)
Если нужно передать массив значений в IN, не нужно писать циклы и подставлять ? вручную. Класс сделает это сам через магический метод BuildParams:

php
$allowedCities = [1, 2, 5, 8];
// Передаем массив просто как значение плейсхолдера :cities
$tickets = $db->query("SELECT \* FROM lift_calls WHERE city_id IN (:cities)", ['cities' => $allowedCities]);
📦 Массовая вставка (Bulk Insert)
Для синхронизации офлайн-заявок, когда нужно записать пачку из 50 тикетов, используйте insertMulti(). Это в десятки раз быстрее, чем вызывать insert() в цикле.

php
$tickets = [
    ['address' => 'ул. Ленина 1', 'details' => 'Не работает'],
    ['address' => 'ул. Ленина 2', 'details' => 'Шумит']
];
$success = $db->insertMulti('lift_calls', $tickets);
// Возвращает true при успехе
🔄 Транзакции (Атомарность)
Если нужно выполнить несколько запросов, и при ошибке в любом из них откатить всё назад:

php
try {
$db->beginTransaction();

    $id = $db->insert('lift_calls', ['address' => '...', 'details' => '...']);
    $db->update('lift_counters', ['total' => 10], ['id' => 1]);

    $db->commit(); // Фиксируем изменения

} catch (Exception $e) {
$db->rollBack(); // Откатываем, если что-то упало
error_log("Ошибка транзакции: " . $e->getMessage());
}
🚀 Итератор для больших выборок
Если из базы нужно вытащить 100 000 заявок, метод query() съест всю оперативную память. Используйте iterator() — он выдает строки по одной:

php
$iterator = $db->iterator("SELECT * FROM lift_calls");
foreach ($iterator as $row) {
// Обрабатываем одну строку. Память не переполняется.
echo $row['id'];
} 4. Обработка ошибок и логирование
Никаких try...catch вокруг базовых запросов: Класс настроен на PDO::ERRMODE_EXCEPTION. Если запрос упадет (например, синтаксическая ошибка SQL), класс перехватит это, запишет в лог и вызовет Exception.

Где искать логи: Все ошибки БД пишутся в папку logs/dataBase/ в корне проекта. Файл называется по дате.

Авто-реконнект: Если MySQL разорвал соединение (ошибка server has gone away), класс автоматически попробует переподключиться до 3 раз, не роняя основной скрипт. Это критически важно для длительных cron-задач.

Кодировка: В DSN-строке жестко зашит utf8mb4. Если у тебя старые таблицы в utf8 (3-байтные), MySQL автоматически сделает даунгрейд на уровне соединения. Ошибок с эмодзи или спецсимволами не будет.
