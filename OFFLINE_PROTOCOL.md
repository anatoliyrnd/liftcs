Версия: 1.1
Статус: Актуально (согласовано)
Последнее обновление: 21.10.2026
Связанные документы: API_PROTOCOL.md, AUTH_PROTOCOL.md

Настоящий документ описывает архитектуру работы SPA в режиме отсутствия сети, структуру локальной базы данных (IndexedDB) и механизм синхронизации отложенных заявок.

🏛️ Общая архитектура (PWA + IndexedDB)
Приложение работает по модели Offline-First.

Справочники (адреса, механики) скачиваются один раз и кэшируются в IndexedDB.

Создание заявок при недоступности сети сохраняется в локальную очередь (outbox).

Синхронизация происходит автоматически при восстановлении связи.

Для работы с IndexedDB используется локальная библиотека idb (обертка над нативным API).

🗄️ Схема базы данных LiftCallsDB
1. Хранилище config (ключ key)
   Хранит справочники и настройки.

app_config: права пользователя и структура меню.

staff_list: список механиков.

dicts: справочники отделов, запросов и групп.

last_user: профиль последнего успешно авторизованного пользователя (для входа в офлайн).

app_settings: пользовательские настройки (например, город по умолчанию).

2. Хранилище address_flat (ключ id)
   Плоский список лифтов (объектов) для мгновенного поиска.

Структура: { id, city_id, city_name, street_id, home_id, display_name, search_string }

Зачем: Позволяет искать адрес одной строкой (улица + дом + лифт) без сложных JOIN-запросов.

Формирование: На основе иерархического JSON от сервера (data: "loadAddress") данные "сплющиваются" утилитой address-flattener.js.

3. Хранилище outbox (ключ uuid)
   Очередь неотправленных заявок.

Структура: { uuid, original_author_id, original_author_name, payload, created_at }

Лимит: В config.js задан MAX_OFFLINE_TICKETS (по умолчанию 50). При достижении лимита создание новых заявок блокируется.

4. Хранилище tickets_cache (ключ id)
   Кэш последнего успешного ответа сервера по спискам open и close. Позволяет отрисовывать таблицу при старте без сети.

🔄 Механизм синхронизации (SyncManager)
Синхронизация запускается:

По событию браузера window.addEventListener('online').

Вручную пользователем (через кнопку в интерфейсе).

При старте SPA (если есть сеть и очередь не пуста).

Алгоритм отправки
Авторизация: Если access-токен истёк, сначала выполняется refresh через auth.php. Если сессия не восстанавливается — синхронизация приостанавливается.

Батчи: Заявки отправляются пачками по 10 штук (SYNC_BATCH_SIZE) в рамках одного POST-запроса с экшеном callNewOffline.

Метаданные: К каждой заявке добавляются поля offline_author_id и offline_author_name (кто создал заявку), а также offline_uuid (для обеспечения идемпотентности).

Обработка ответа:

Сервер обрабатывает пачку атомарно (либо сохраняет все заявки, либо отклоняет всю пачку целиком).

При успехе ({status: "ok"}) фронтенд удаляет отправленные заявки из outbox по их offline_uuid.

Важно: Сразу после удаления из outbox фронтенд делает отдельный запрос { "data": "open" } для получения актуального списка заявок. Полученный массив перезаписывает tickets_cache и обновляет таблицу в памяти.

Ошибки: Делается до 5 попыток (MAX_SYNC_RETRIES). Если не удалось — выдается диалог. Пользователь может попробовать снова или дважды подтвердить удаление всех офлайн-заявок и продолжить работу в онлайне.

🔐 Офлайн-авторизация (Автономный доступ)
Если сеть пропала, но в IndexedDB есть профиль last_user:

SPA не выкидывает пользователя на экран логина.

Включается режим «Автономный доступ» (только чтение журнала и создание офлайн-заявок).

При появлении сети SyncManager делает refresh. Если сессия недействительна — просит перелогиниться, сохраняя очередь заявок нетронутой.

🖥️ Отображение офлайн-данных
Журнал: Офлайн-заявки отображаются в общем списке с иконкой ⏳.

Карточка: Открывается в режиме read-only. Кнопки «Редактировать» и «Закрыть» скрыты. Сверху висит желтая плашка «Ожидает синхронизации».

Фильтры:

Фильтр по городам (чекбоксы). Минимум один город всегда выбран.

Скрыть заявки со сроком ремонта > 14 дней (параметр вынесен в config.js).

Применяются только к открытым заявкам.
